# 動物病院予約管理アプリ（設計ポートフォリオ）

簡単に予約でき、待ち時間なく受診できるアプリの企画・要件定義書です。

## 🌐 本番環境について
本リポジトリは、Webアプリケーション開発演習における**「企画・要件定義・データ設計」の成果物（設計ポートフォリオ）**です。
現在は基本設計およびデータ構造の定義フェーズであり、実際のアプリケーションの公開（デプロイ）は行っておりません。

---

## 🎯 目的・ゴールの整理

### 1. アプリが何のためのものか
飼い主が待ち時間なく受診できるよう手軽に予約ができ、満足度を上げるため。

### 2. アプリを使うことで何が達成されるか（ユーザーゴール）
飼い主が待ち時間なく受診できるようにし、患者（ペット）の負担を減らすようにする。

### 3. 運用する側として何を実現したいか（ビジネスゴール）
予約管理をデジタル化してスタッフの受付負担やミスを減らし、スムーズな案内で病院の評価や満足度を向上させる。

---

## 👥 利用者・利用場面の整理

### 1. このアプリを誰が使うのか
- 飼い主
- 病院スタッフ

### 2. 利用者がどのような立場・役割で使うのか
- **飼い主**: 「ペットの診察予約や混雑状況の確認、呼び出し通知を受け取る立場」として利用する。
- **スタッフ**: 「日々の予約状況の確認、受付時間や休診日の変更、来院履歴の管理を行う立場」として利用する。

### 3. どのような場面でこのアプリを使うのか
- **飼い主**:
  - ペットの体調不良で受診したいとき
  - 定期健診や予防接種などで来院する際
  - 院内での長い待ち時間を避けたいとき
- **病院スタッフ**:
  - 毎朝の予約状況や患者情報を確認したいとき
  - 急な休診日や受付時間の変更を登録したいとき

### 4. どのような環境（デバイス）で使うのか
- **飼い主**: 外出先や自宅から、個人のスマートフォン（SafariやGoogle Chromeなど）から利用。
- **スタッフ**: 病院の受付にあるPCやタブレットのブラウザ（Google Chromeなど）から利用。

## 🛠 要件定義（機能一覧）

### 💡 今回の設計対象（実装すること）
- ログイン機能（IDとパスワードによる認証）
- 時間帯予約機能（希望日時とペット情報を入力して予約）
- 呼び出し通知機能（診察順が近づいた際にアプリ内通知を受信）
- 患者情報連携機能（登録されたペット情報をスタッフと共有）
- 受付時間・休診日の設定機能（スタッフによる登録・変更）
- 来院履歴管理機能（スタッフによる来院履歴の更新・管理）

### ⏭ 次回以降の課題（今回の対象外）
- 事前問診入力機能
- デジタル診察券機能

## 🏃‍♂️ 利用者の操作フロー・権限の違い

### 飼い主の操作流れ
1. ログインする
2. 時間帯予約を入れる
3. 順番が近くなったら呼び出し通知を受け取る

### 病院スタッフの操作流れ
1. 管理画面にログインする
2. 当日の予約一覧を確認する
3. 必要に応じて休診日の設定や来院履歴の更新を行う

### 利用者ごとに使える機能や操作の違い
- **飼い主**: ログイン、時間帯予約、呼び出し通知の受信、患者情報連携ができる。
- **スタッフ**: 上記の全機能に加え、受付時間の設定、休診日の設定、全体の来院履歴の管理ができる。
